# Security

The demo API uses one shared bearer key set through `SAGA_API_KEY`. Use a dedicated secret manager and rotate keys through a controlled rollout in an actual environment. The console holds the key in memory, not persistent browser storage; do not expose the console or API publicly without TLS and appropriate identity and authorization. Keep Kafka and Redis on private networks with authentication and TLS. Restrict who may publish to `saga.results`, because result events authorize workflow transitions. Limit access to `/actuator/prometheus` and `/actuator/health` through ingress policy. Do not put payment credentials or sensitive order data in commands; only opaque IDs are intended. Report vulnerabilities privately to the repository owner rather than opening a public issue with exploit details.
